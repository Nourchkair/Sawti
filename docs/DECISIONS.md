# Sawti implementation decisions

Decisions are dated. A “proposed” decision is not runtime proof.

| ID | Date | Decision | Reason / status |
|---|---|---|---|
| D-001 | 2026-10-18 | Start from upstream commit `a4f6af6df2674bc4e18097084a128af469823fab` on local branch `sawti/dev` | This is the reviewed main commit; upstream `main` still resolved to this SHA at setup. No upstream patch head is assumed merged. |
| D-002 | 2026-10-18 | Keep Sawti fully separate from AcademiaOS through 1.0 | User-approved product scope. No AcademiaOS files, schema, process, import path or release dependency is included in Sawti work. |
| D-003 | 2026-10-18 | No production code or broad refactor before the helper feasibility gate | User-approved v1.1 execution order. First establish app/helper identity, permissions, actual audio handoff and kill/teardown behavior. |
| D-004 | 2026-10-18 | Candidate Sawti identity is `com.nourchkair.sawti`; the P0.4 development probe uses an isolated development suffix | Validate registration and live TCC attribution. It is a proposed identifier, not a registered Apple identity. Revalidate after every identity/signature change. |
| D-005 | 2026-10-18 | Work from Nour's personal fork; keep upstream fetch-only | `origin` is `https://github.com/Nourchkair/meeting-transcriber.git`; `upstream` is `https://github.com/pasrom/meeting-transcriber.git` with `remote.upstream.pushurl=disabled://sawti-upstream-read-only` and `push.default=nothing`. Push development branches only to the personal fork. |
| D-006 | 2026-10-18 | Keep model, feature and dependency pins unchanged during the feasibility probe | Avoid combining architecture evidence with model/download/dependency changes. Any version update needs its own measured regression case. |
| D-007 | 2026-10-18 | Do not install system developer tools or create/install a signing identity silently | At the initial 2026-10-18 baseline, the host had Swift 6.0.3 and zero valid signing identities. The current environment and probe identity are recorded in `docs/validation/VALIDATION.md`; a stable code signature is still required for a meaningful GA capture test. |
| D-008 | 2026-10-18 | MacBook Air M2/8 GB is accepted as the development target | User confirmed this host is an acceptable development target. Use it for the early feasibility probe and Sawti milestones. This does not establish performance or thermal equivalence with a MacBook Pro; qualify Pro separately only if Sawti's release support claims include that model. |
| D-009 | 2026-10-19 | An ad-hoc signature may be used for a one-build diagnostic, but does not pass the stable-signing/TCC gate | Apple documents that an ad-hoc signature has no signing identity and its designated requirement is tied to that exact code version; macOS cannot reliably track microphone authorization across rebuilds. This is why the GA/P0.4 acceptance check requires a stable development identity. This is an inference from [Apple TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements), not a runtime result from this host. |
