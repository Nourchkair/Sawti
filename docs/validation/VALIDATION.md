### Sawti Alpha implementation evidence (2026-10-19)

The in-bundle `SawtiCaptureHelper` product is built and embedded by the development and release scripts. The production capture factory selects it only for microphone-only sessions with no live sink or debug fault; existing app-audio and dual-source routes are preserved. The helper sends bounded JSON health/control events over stdio and writes audio directly to the recording path, keeping audio and transcript contents out of the IPC channel. Automated tests cover routing, partial status frames, unexpected exit reporting, graceful-stop state, transcript versioning, owner-only mode, preservation across speaker naming, error-state access, and output cleanup after retrying into a different folder.

The transcription pipeline writes the original engine-returned segment text before normalization, VAD timestamp remapping, echo filtering, diarization or speaker naming. It writes the final transcript separately, and the menu exposes both when present. Export creates a copy and does not rewrite either artifact. The original file uses owner-only mode (`0600`). This protects Sawti's writes; it does not prevent the user or another process with the same account from editing or deleting the files.

The isolated XCTest invocation after the retry-cleanup change discovered 3,468 tests and exited 0; a later full wrapper run discovered 3,469 and passed. The wrapper excludes real model-preload tests and gates model-backed tests unless explicitly opted in. The latest release-configured runtime smoke bundle was signed with the self-signed Sawti development identity through the explicit `SAWTI_DEV_SIGNING_IDENTITY` override and passed strict verification. The selected ASR model required a one-time download before use; the core workflow uses no paid transcription API, and protocol generation/update checks default off. Measured model initialization took about three minutes on two successive launches. TCC clean-install continuity, long-recording ground-truth accuracy, peak memory/thermal behavior, and MacBook Pro-specific behavior remain qualification items; app-audio capture is deferred to Beta. `scripts/lint.sh` could not run because `swiftformat` and `swiftlint` are not installed.

### Real helper-backed force-quit recovery (2026-10-19)

In a disposable `SAWTI_TEST_HOME`, the signed development app started a real microphone-only recording through its in-bundle helper. The app process was force-quit while the helper was writing. On relaunch, the helper had exited and the cold-start repair/re-mix path produced a valid WAV: 49.104625 seconds, mono 16 kHz, 16-bit PCM, 785,674 frames, 1,575,444 bytes. The `_mic.wav` and recovered `_mix.wav` had identical SHA-256 `062773fa060dc952cd760c4671e4972ce5e7da0305fb11314589ff8a3f3d19b5`, establishing byte-for-byte preservation of the helper's finalized file through the remixer. The app discovered the new mix and persisted one `Recovered Recording` pipeline job after relaunch.

The first live attempt, using the prior build, exposed a migration-order bug: when no legacy ledger existed, startup remixed the crash track before ledger migration, then migration seeded that new mix as already processed and orphan recovery skipped it. The fix migrates the ledger before startup repair/remix, passes the injected recordings directory through orphan recovery, and persists an empty `[]` ledger on a successful empty scan so later recovery output cannot be mistaken for pre-existing audio. Regression coverage verifies both that an older mix remains skipped and a newly recovered mix is queued; the focused `StagedRecoveryFolderTests` and `ProcessedRecordingsLedgerTests` run passed all 9 tests.

After a real helper-backed force-quit and cold-launch recovery, the job restored from the persisted queue and entered `transcribing`. The initial retry did not finish within the first bounded checks. A subsequent uninterrupted retry, with 8.6 GB free after removal of six stale temporary Core ML bundles created by earlier interrupted Sawti test processes, loaded WhisperKit in 185.36 seconds, transcribed the recovered audio, completed offline diarization, and saved both original and final transcript text plus its segment sidecar. A follow-up app launch loaded the model in 180.55 seconds and created another process-specific approximately 1.2 GB temporary Core ML bundle; the app remained alive and disk headroom stayed above 6 GB. This indicates repeated slow model initialization on this host, although successful transcription is confirmed. The recovered WAV is 49.104625 seconds, mono 16 kHz, 16-bit PCM, 785,674 frames, 1,575,444 bytes. The preserved mic, recovered mix and pipeline output WAV copies share SHA-256 `062773fa060dc952cd760c4671e4972ce5e7da0305fb11314589ff8a3f3d19b5`; ASR produced three timestamped segments ending at 45.14 seconds and the diarizer labeled one speaker `S1`. The original and final transcript texts contain the same 43-word token sequence; all generated files were `0600`. The queue remained at the manual speaker-naming step because no real-world speaker name was available. No app-audio or system-audio capture was involved. The isolated app was then stopped; no Sawti app or helper remains running. WAV and transcript artifacts remain in the disposable isolated test home and were not added to the repository. These observations do not establish peak total memory, thermal stability, broad transcript accuracy, or MacBook Pro-specific performance; the offline check is accepted by the user.

## Evidence rules

- Store only disposable test signals/recordings under an explicit temporary Sawti probe root. Never copy from `~/Library/Application Support/MeetingTranscriber`, Nour's personal recordings or AcademiaOS.
- Record bundle identifier, signing identity/designated requirement, process ancestry, permission state, OS/build, channel configuration, saved file hashes and frame counts with each capture attempt.
- A granted TCC entry, successful `start()` return or zero application error is not proof of audio delivery. Analyze the bytes written by the helper and a known marker in each required source.
- A blocked startup/stop test passes only when the UI remains responsive, the unaffected channel persists independently and the declared supervisor policy actually terminates or latches the failed helper.
- Run the routine XCTest suite through `scripts/test-isolated.sh`, which supplies disposable HOME/AppPaths roots, clears inherited `FFMPEG_BINARY`, snapshots protected IPC paths and uses process-local defaults and keychain test stores. Keep real model, microphone, system-audio and TCC checks in their explicit qualification lanes; before each, record the command, toolchain, environment, fixture and every skipped test.
