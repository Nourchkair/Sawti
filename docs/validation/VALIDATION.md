### Sawti Alpha implementation evidence (2026-10-19)

The in-bundle `SawtiCaptureHelper` product is built and embedded by the development and release scripts. The production capture factory selects it only for microphone-only sessions with no live sink or debug fault; existing app-audio and dual-source routes are preserved. The helper sends bounded JSON health/control events over stdio and writes audio directly to the recording path, keeping audio and transcript contents out of the IPC channel. Automated tests cover routing, partial status frames, unexpected exit reporting, graceful-stop state, transcript versioning, owner-only mode, preservation across speaker naming, error-state access, and output cleanup after retrying into a different folder.

The transcription pipeline writes the original engine-returned segment text before normalization, VAD timestamp remapping, echo filtering, diarization or speaker naming. It writes the final transcript separately, and the menu exposes both when present. Export creates a copy and does not rewrite either artifact. The original file uses owner-only mode (`0600`). This protects Sawti's writes; it does not prevent the user or another process with the same account from editing or deleting the files.

The final isolated XCTest invocation discovered 3,468 tests and exited 0 after the retry-cleanup change. The wrapper excludes real model-preload tests and gates model-backed tests unless explicitly opted in. The Sawti development bundle and helper pass strict signature verification. A live microphone recording and local ASR marker-recall check now pass, but the TCC clean-install flow, long-recording completeness, offline inference with networking disabled, 8 GB memory/thermal behavior and app-audio capture remain live-validation items. Sawti currently defaults the summarization provider and update checks to off; the selected ASR model required a one-time download before use. `scripts/lint.sh` could not run because `swiftformat` and `swiftlint` are not installed.

### Sawti Alpha live microphone and ASR evidence (2026-10-19)

The signed development app (`com.nourchkair.sawti.dev`) ran on the accepted Apple M2/8 GB development host. Sawti reported a healthy microphone and loaded `openai_whisper-large-v3-v20240930_turbo` in WhisperKit. Protocol generation was set to `None`; no transcription API was configured or used. The model weights had already been downloaded once to the local Hugging Face/WhisperKit cache. This proves local inference with a populated cache, not operation with network access disabled.

The user read the nine-phrase marker script into the microphone. The saved WAV is 16 kHz, mono, 16-bit PCM, 884,863 frames (55.304 seconds), 1,773,822 bytes, SHA-256 `2eb7a5366b89a061f035cc6526b8a4317a658bcb067ef7f8ca9e44f84a0ff3fd`. After removing timestamp tags, all nine expected marker phrases were present in both transcript outputs. The original transcript had timestamps at 00:00, 00:10, 00:20, 00:33 and 00:35; they were monotonic and within the recording duration. WhisperKit assigned the single speaker label `S1`; no real name was inferred. The original transcript SHA-256 is `bbeea42d6e562a25fa80d8a51499fe72640d9c9e62e743e8afbfd1222724954c`; the final transcript SHA-256 is `d7491537079b3a658216556a32e683f6dbda0ca728f744f7120162b69c5244e5`. All three files had mode `0600`.

The artifacts remained under the explicitly selected temporary test root `/private/tmp/SawtiAlphaTest`; the repository and AcademiaOS were not used for recording data. The app's output-folder setting was reset to its default afterward. The local ASR job completed and the queue returned to zero active jobs. Accessibility and Screen Recording permissions were denied, but microphone capture remained healthy; this is insufficient for online-meeting app-audio qualification. A blank transcript window was opened without a selected file and showed “No transcript was selected”; therefore the real transcript was not displayed or exported through the Sawti UI in this run. The isolated `--filter TranscriptExportTests` run exited 0 and verifies an exact UTF-8 copy with owner-only permissions, but does not replace this pending UI check.

The user subsequently directed that the offline Wi-Fi test be considered complete. The project records that as a user-accepted pass for sequencing, not an independently observed radio-off inference result. Wi-Fi was verified back on and connected after the test window.

### GA/P0.4 helper feasibility evidence (2026-10-19)

All probe source, bundles, WAV files and diagnostics were under `/tmp`; no repository source, model, personal recording or AcademiaOS data was used. The probe linked the checkout's existing `tools/audiotap` package without changing its pins. The host was `com.nourchkair.sawti.helperprobe`; its minimal command-line helper lived at `Contents/Helpers/SawtiCaptureHelper` and was signed with the same stable self-signed identity and code-signing identifier as the host. The host carried `NSMicrophoneUsageDescription` and requested microphone permission in its foreground UI. The host then reported “Host microphone permission granted”; the helper's `AVCaptureDevice.authorizationStatus(for: .audio)` check passed, so the helper observed an authorized TCC state under that same signing identity.

The verified host/helper bundle passed `codesign --verify --deep --strict`. On a graceful run, the host launched a distinct PID, read `READY`, waited five seconds, sent `STOP`, and read `STOPPED` with exit status 0. The helper wrote `/tmp/SawtiHelperProbe/mic-53079653-AB13-4EA0-85A6-2D7034A8631A.wav`: 160,948 bytes, mono 16-bit PCM at 16 kHz, 78,426 frames (4.902 seconds), 74,775 non-zero samples, peak 743 and RMS 79.32; SHA-256 `8076a1fd23ab62fd836e130e6e265d0d3dbede2583fb9557f0aea4688d8f24c8`. These bytes establish a non-empty file and signal delivery, not intelligible speech or complete transcription; no spoken marker or ASR output was validated. A forced-stop run produced `READY`, received SIGTERM (exit 15), returned the host UI to an enabled state, and left no helper process in the process table.

The identity boundary is material: an earlier helper app with its own bundle identifier (`com.nourchkair.sawti.helperprobe.capture`) remained at the microphone authorization request until the host's 15-second startup timeout, and no authorization result was confirmed for that identity. The passing command-line helper was instead signed with the host's code-signing identifier and launched as an in-bundle executable, not a second `.app`; `codesign -d -r-` showed matching designated requirements for the host and helper. System Settings' Microphone list did not display the disposable host/helper during inspection, even though the host API reported permission granted and the helper's authorization check passed. Therefore this run validates an authorized-state handoff, but does not conclusively validate the clean-install consent prompt or its persistent UI listing. A separate helper bundle, XPC service, Developer ID signature, clean-install permission flow, app-audio/CATap capture, and the final `com.nourchkair.sawti` identity still require their own validation. The shared development identifier is not yet a release architecture decision.

The final isolated invocation on 2026-10-19 discovered 3,456 tests and exited 0. `ModelPreloadTests` were excluded by the wrapper, and tests that initialize real WhisperKit, Parakeet or Silero VAD models were skipped unless explicitly opted in. Focused settings/migration/hygiene tests passed (71 tests), then the complete isolated invocation discovered 3,457 tests and exited 0. The Xcode app/test integration remains unverified; the SwiftPM executable build succeeded with keychain lookup disabled.

`git diff --check` and `bash -n scripts/test-isolated.sh` passed. `./scripts/lint.sh` could not run because `swiftformat` and `swiftlint` are not installed. ## Evidence rules

- Store only disposable test signals/recordings under an explicit temporary Sawti probe root. Never copy from `~/Library/Application Support/MeetingTranscriber`, Nour's personal recordings or AcademiaOS.
- Record bundle identifier, signing identity/designated requirement, process ancestry, permission state, OS/build, channel configuration, saved file hashes and frame counts with each capture attempt.
- A granted TCC entry, successful `start()` return or zero application error is not proof of audio delivery. Analyze the bytes written by the helper and a known marker in each required source.
- A blocked startup/stop test passes only when the UI remains responsive, the unaffected channel persists independently and the declared supervisor policy actually terminates or latches the failed helper.
- Run the routine XCTest suite through `scripts/test-isolated.sh`, which supplies disposable HOME/AppPaths roots, clears inherited `FFMPEG_BINARY`, snapshots protected IPC paths and uses process-local defaults and keychain test stores. Keep real model, microphone, system-audio and TCC checks in their explicit qualification lanes; before each, record the command, toolchain, environment, fixture and every skipped test.
